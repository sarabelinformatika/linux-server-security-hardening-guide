# Contributing

Contributions that improve accuracy, safety, portability, or operational usefulness are welcome.

1. Open an issue describing the platform, release, use case, and proposed change.
2. Keep examples non-destructive and free of real secrets or customer data.
3. Prefer primary vendor or standards sources.
4. Run the validation workflow locally where practical.
5. Explain operational impact, rollback, and distribution differences in the pull request.

Security vulnerabilities must be reported through the process in [SECURITY.md](SECURITY.md), not a public issue.
